# Task Checkpoint

先定位当前任务所属的项目根目录，再使用该项目的 `04_文档/进行中任务.md`，不要把路径解释为无关的临时 cwd。优先使用用户指定或已确认属于当前任务的记录；若默认文件属于其他任务，保留它并将当前记录保存为 `04_文档/进行中任务/<task-id>.md`。在记录开头写明项目、任务标识与更新时间，供跨设备、跨会话恢复时核对。

## 收尾（保存状态）

1. 逐段核对当前对话与工作区文件，只写事实。
2. 只更新已确认属于当前任务的记录；新任务使用独立记录。保留与其他任务有关的内容，正文保持五段模板：
   - 任务：当前在做什么，一句话
   - 进度：已完成 / 进行中
   - 下一步：下个会话要做的第一个动作
   - 阻塞：卡住的事项，没有则写"无"
   - 本轮结论：这轮的关键判断，一行以内
3. 完成标准：记录的项目和任务归属正确，五段全部反映真实状态；读回验证后报告保存路径。

## 开工（恢复状态）

1. 读取用户指定或与当前项目、任务匹配的记录；文件不存在则简报"无记录"。多个任务无法区分时，仅询问要恢复哪一个。
2. 向用户简报：任务、进度、下一步、阻塞。
3. 核对“下一步”与当前文件状态。用户已要求恢复并继续时，在已有授权范围内推进；仅要求查看状态时只简报。记录已过时、必要目标不明或需要新授权时再提问。
4. 完成标准：简报覆盖四段；若用户要求继续，已完成可推进的下一步或明确报告必要阻塞。
