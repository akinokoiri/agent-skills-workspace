# 非技术用户现象澄清与防锚定指南 (Symptom Interview Guide)

## 一、 核心原则：现象学还原 (Phenomenological Inquiry)
当用户反馈模糊问题（如“系统很卡”、“打不开了”、“功能挂了”）时：
1. **不要预设结论**：用户的词汇往往包含错误归因（如把“内网 NAS 慢”说成“电脑卡”）。
2. **禁用专业术语质问**：不要问“是哪个 API 返回 500 了吗？”，非专业用户只会回答“可能吧/不知道”。
3. **还原动作与感官**：引导用户回到产生问题的第一瞬间。

---

## 二、 标准现象澄清提问模板

### 1. 动作还原（你在做什么？）
* ❌ *错误提问*：“你调用的是哪个模块的服务？”
* ✅ *正确提问*：“你当时是在进行什么具体操作？（例如：点击了某个界面的保存按钮、还是刚打开软件正在加载？）”

### 2. 感官表现（你看到了什么？）
* ❌ *错误提问*：“客户端收到 RST 还是 Timeout？”
* ✅ *正确提问*：“屏幕上具体出现了什么反应？（例如：没有任何反应、一直出现转圈图标、直接闪退，还是弹出了具体的提示框？如果弹窗，上面的文字是什么？）”

### 3. 参照物比对（其他东西正常吗？）
* ❌ *错误提问*：“当前链路的带宽和丢包率正常吗？”
* ✅ *正确提问*：“在出现该现象的同时，其他操作正常吗？（例如：访问其他网页快不快？本地打开其他软件卡不卡？）”

### 4. 时间与变化（何时开始的？）
* ❌ *错误提问*：“系统基线何时漂移的？”
* ✅ *正确提问*：“这个情况是第一次出现，还是一直如此？在出现问题前，有没有做过什么特殊操作（如更新系统、重启路由、修改文件）？”

---

## 三、 XY 问题识别与纠偏表

| 用户原始说法 | 潜在的错误技术归因（勿盲信） | 现象学还原提问 | 真实可能根因 |
| :--- | :--- | :--- | :--- |
| “我电脑非常卡” | 内存占满、CPU 爆了、硬盘老化 | “是桌面拖动卡、打字卡，还是特定打开某个网络文件时卡？” | 挂载的内网共享/NAS 响应超时，导致资源管理器阻塞 |
| “网络断了” | 本机网卡损坏、网线断开 | “右下角网络图标有叹号吗？其他网页能打开吗，还是只有某一个软件打不开？” | 局部 DNS 解析失败或特定服务器宕机 |
| “软件坏了用不了” | 软件核心崩溃、需要重装 | “点击软件图标后发生了什么？是完全没弹窗口，还是弹窗后卡住？” | 配置文件权限被锁定或端口被占用 |
