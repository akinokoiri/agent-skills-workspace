# 生产一致性与真实验证指标对照表 (Production Parity & Metrics)

## 一、 为什么“测试通过 ≠ 生产通过”？
Agent 容易在高度简化的本地环境中得出“问题已修复”的假象。这是因为本地环境通常缺少生产环境的关键约束：
1. **网络拓扑差异**：本地没有真实的网络延迟、丢包、NAT 穿透、代理网关及 TLS 握手开销。
2. **数据规模与并发**：本地测试通常使用单条记录或空数据，无法触发死锁、连接池耗尽、大数据反序列化慢等问题。
3. **权限与隔离**：本地进程通常拥有完整权限，生产容器/沙箱中可能受到严格的只读文件系统、跨域 (CORS) 或安全组限制。

---

## 二、 “真假验证指标”对照表

在评估修复效果时，严禁使用“粗粒度连通性”替代“真实业务健康度”：

| 故障类型 | ❌ 欺骗性指标 (伪修复验证) | ✅ 真实业务有效指标 (真修复验证) | 说明 |
| :--- | :--- | :--- | :--- |
| **网络/页面卡顿** | `ping domain.com` 延迟低（仅代表 ICMP 连通） | 完整 `curl -w "@format" https://domain.com` 统计 DNS+TLS+TTFB+下载耗时；浏览器首屏渲染时间 (FCP) | Ping 正常完全无法反映 TLS 阻塞、HTTP 504 或大包传输阻塞 |
| **接口性能问题** | 单次本地直接调用返回 200，耗时 5ms | 携带真实大小 Payload、模拟生产网络延迟与并发下的 P99 响应时间 | 忽略网络传输、序列化成本和并发竞争 |
| **数据库/存储卡死** | 简单 `SELECT 1` 或查空表秒回 | 模拟实际数据量级下的慢查询计划 (EXPLAIN ANALYZE) 及锁等待状态 | 无法暴露索引失效与全表扫描 |
| **文件写入异常** | 本地写 `/tmp` 目录成功 | 目标生产挂载点（如 NAS/NFS/只读卷）的实际写入与权限校验 | 本地临时目录无法复现分布式锁和存储配额限制 |

---

## 三、 验证结案时的“盲区声明 (Blindspot Disclosure)”模板

当由于客观环境限制，Agent 无法在 100% 贴合生产的环境中完成全链路验证时，**结案报告必须包含以下声明块**：

```markdown
### 🔍 验证结果与生产差异声明
* **已在当前环境验证通过项**：
  - [x] 修复逻辑已通过单变量自动化测试（附用例代码及结果）。
  - [x] 模拟数据流在断点层级无异常。
* **⚠️ 潜在生产环境差异与测试盲区**：
  - [ ] **网络与拓扑**：本地未经过生产 WAF/反向代理层，需注意线上 Header 转发规则。
  - [ ] **数据量级与负载**：当前仅验证了单并发场景，未进行高并发压力测试。
  - [ ] **外部依赖**：下游第三方服务目前使用了 Mock 桩，上线前需做端到端冒烟测试。
```
